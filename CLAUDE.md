# Stroll

Stroll is an audio-first walking guide: a watchOS app (buzz, photo preview, narration in
earbuds) with an iPhone companion app (map of points of interest, Journal). Team: Mara
(design lead), Flora (Xcode, watch, Apple developer account), MJ, and whoever handles
location research.

## Read first

- **`docs/round1-plan.md` is the source of truth** for what we're building in round 1. Where
  it disagrees with other docs or the code's comments, it wins. Don't change it without the
  team's agreement.
- `docs/git-workflow.md`: how the team uses Git.
- `docs/WATCH-EXPLORING-CHANGES.md`: planned watch changes (deferred until before testing).
- `docs/location-research-guide.md`: how new stops are researched and handed over.

## Git rules

- **Never push to `main`** or merge into it yourself. Work on a new branch named
  `yourname/task`, then open a pull request.
- Keep each branch to one small task, and start it from the latest `main`.
- Flora reviews anything that changes app code, since only she can build and run it on the
  iPhone and watch.

## Project notes

- `Stroll.xcodeproj` is generated by XcodeGen from `project.yml` and isn't in Git. Run
  `xcodegen` after pulling or adding/removing files. Change build settings, capabilities and
  targets in `project.yml`, never in Xcode's settings screens.
- Layout: `Watch/` (watch app), `Phone/` (iPhone app, becoming the companion), `Shared/`
  (content and phone↔watch messages, used by both), `Resources/` (narration clips, photos),
  `Tools/check-walk-model.sh` (runs the walk logic on a Mac without Xcode),
  `web-prototype/` (browser prototype from the first interviews).
- Targets iOS 17 and watchOS 10, Swift 5. Bundle IDs `com.teamgreen.stroll.remote` and
  `com.teamgreen.stroll.remote.watchkitapp`.
- Brand green is `#2F6B4F`; match the Figma file **AxD-Stroll**, page "iPhone app – MVP".
- Never commit API keys or passwords (for example the ElevenLabs key for
  `web-prototype/tools/make-voice.mjs`); keep them in environment variables.
- Several teammates are designers: explain technical trade-offs in plain language and give a
  recommendation.
